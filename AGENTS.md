# Agent Notes

## Repo Shape
- Single-package Node.js CLI. Main entrypoint is `src/index.ts`; core behavior lives in `src/config.ts`, `src/sshTunnel.ts`, and `src/schemaSync.ts`.
- `dist/` is generated by `npm run build` from `src/` and is gitignored. Edit `src/*.ts`, not `dist/*`.

## Commands
- Install deps with `npm install` (lockfile is `package-lock.json`, so use npm, not pnpm/yarn).
- `npm run build` is the only built-in verification command. There are no repo scripts for test, lint, or separate typecheck.
- Dry-run sync: `npm run sync`
- Real schema apply: `npm run sync:apply`
- Focused runs must pass args after `--`, for example: `npm run sync -- --include users orders` or `npm run sync -- --include-data users orders --apply`
- `--include-data` is a convenience flag from `src/index.ts` that populates both `--include` and `--data` with the same tables.

## Runtime Behavior
- `src/config.ts` loads `.env` automatically via `dotenv` at process startup; CLI flags override env values.
- `--data` tables are automatically added to the effective include list in `loadConfig()`. Do not treat data-copy requests as separate from schema selection.
- Schema diffs are handled by full table rebuilds, not `ALTER TABLE`: on mismatch the tool drops and recreates the local table from remote `SHOW CREATE TABLE`.
- Data copy is destructive to local table contents: `copyTableData()` truncates the local table before inserting remote rows.
- Data copy currently loads the full remote result set into memory before chunked inserts; be careful with large tables.
- Foreign key checks are disabled once per run before destructive local operations and restored in `finally`.
- DDL comparison normalizes away only `AUTO_INCREMENT=<number>` differences. Other DDL differences will trigger a rebuild.

## Output Quirks
- `--json` is not pure machine-readable JSON right now: `src/index.ts` prints two human log lines before the JSON payload. Do not assume stdout can be parsed as JSON without stripping the banner lines.
- The process sets `exitCode = 1` when per-table errors occur, even if other tables succeed.

## Environment Gotchas
- Real runs depend on local access to `.env` values, especially a readable SSH private key path and a reachable local MySQL target.
- Defaults are opinionated toward this repo's environment (`SSH_HOST=13.0.0.1`, remote `kyodb` RDS, local MySQL `127.0.0.1:3306`). Verify before running `sync:apply`.
